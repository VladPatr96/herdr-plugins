# 0001. Свой плагин вместо форка чужого

- **Статус:** принято
- **Дата:** 2026-09-22

## Контекст

Для задачи «файловый менеджер в herdr по хоткею» в каталоге нашёлся `alexarthurs/herdr-sidebar` (368★, MIT): дерево файлов в панели, просмотр, экспериментальный редактор с явным сохранением, документированная Windows-ветка действий. Он почти закрывал замысел, и напрашивался форк.

Два предыдущих плагина проекта (`agent-hotkeys`, `quota-board`) писались с нуля по другой причине: тогда все найденные аналоги объявляли только macOS и Linux. Здесь этот довод не работал — готовое с Windows существовало.

## Решение

Пишем свой плагин на Node 18+ без зависимостей и без сборки, `platforms` включает `windows`. Чужой плагин используем как источник решений: границы просмотра (1 МиБ, 5000 строк, бинарь и битый UTF-8 — только чтение), правка отдельным режимом с явным сохранением и эталоном из сырых прочитанных байтов вместо mtime, ленивое дерево, раскладка клавиш без Alt.

Причина — цена, а не лицензия: оба репозитория под MIT. `herdr-sidebar` — это ~976 КБ Rust в 25 файлах, и половина объёма решает не нашу задачу (панель git с ИИ-сообщениями коммитов, аннотации, превью картинок и кадров видео, работа мышью). Форк означал бы сопровождение чужой кодовой базы, на порядок большей самой задачи; перенос его кода на Node — не перенос, а написание своего менеджера с чужим кодом в роли образца.

## Альтернативы

- **Форкнуть и править Rust.** Дёшево на старте: Rust на машине есть, herdr уже собирался и патчился из форка. Отвергнуто из-за цены сопровождения и того, что половина кода не нужна.
- **Поставить готовый и жить с ним.** Отвергнуто человеком до проверки: нужен свой плагин, а не чужой с его ограничениями.
- **`herdr-nvim`** — единственный плагин каталога, который правит файлы и объявляет `windows`. Его пикер — не дерево папок, а fuzzy-поиск по `git ls-files`, и README Windows не упоминает вовсе.

## Последствия

- Windows-слой чужих плагинов нам не нужен: GUI-сайдкар и `pane split` с подстановкой `PATH` обходят запрет herdr на относительный **исполняемый файл**, а команда нашей панели — `node` из `PATH` плюс относительный путь к скрипту. Так устроен `quota-board`, и на этой машине он работает.
- Всё, что чужой плагин уже прошёл, нам предстоит пройти самим: кодировки, BOM и CRLF при сохранении, большие каталоги, симлинки и junction, отличение текста от бинарного.
- Разбор `herdr-sidebar` записан в задаче [#19](https://github.com/VladPatr96/herdr-plugins/issues/19) и остаётся справочником по ходу работы.
