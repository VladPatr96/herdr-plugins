# Задача #20: что сделать вам

Задача: https://github.com/VladPatr96/herdr-plugins/issues/20

Плагин `agent-tasks` собран и проверён живыми запусками. Осталось включить его
строку в сайдбаре — это единственное, чего агент за вас сделать не может: в
`config.toml` лежат ваши хоткеи, и ломать его мимо вас нельзя.

## 1. Добавить строку задачи в сайдбар

herdr показывает токены плагина только там, где вы их попросите. Сейчас у вас
в `%APPDATA%\herdr\config.toml` две строки агента:

```toml
[ui.sidebar.agents]
rows = [["state_icon", "machine", "workspace", "tab"], ["agent", { token = "$hotkey", align = "right", fg = "#f9e2af", bold = true }]]
```

Замените на три — третья и есть задача:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "machine", "workspace", "tab"],
  ["agent", { token = "$hotkey", align = "right", fg = "#f9e2af", bold = true }],
  [{ token = "$task", bold = true }, { token = "$task_progress", align = "right", fg = "#a6e3a1" }],
]
```

> `align` понимает только ваша сборка herdr (`VladPatr96/herdr@sidebar-token-align`).
> Стоковый herdr её отвергает — там уберите `align` из обеих строк.

Потом:

```
herdr server reload-config
```

Строка **пропадает у агентов, запущенных не этим плагином**: herdr прячет
строку, у которой ни один токен не заполнен. Остальные агенты выглядят как
раньше.

Заголовок задачи, впрочем, виден у вас уже сейчас: плагин кладёт его и в
название вкладки, а `tab` стоит в первой строке. Третья строка добавляет к
нему прогресс плана (`4/4`) и текущий пункт.

## Что известно про codex

Codex запускается тем же способом и **попадает в общий список**: своя вкладка,
своя задача в сайдбаре, свой хоткей, статус, строка на доске — это проверено.
Но **отвечать он на этой машине сейчас не может**, и плагин тут ни при чём:

- `codex` в этой папке, запущенный вручную (без herdr), падает с
  `windows sandbox failed: timed out after 15000ms connecting runner pipe-in`;
- в другой папке он доходит до композитора, но остаётся в `model: loading` и
  копит ввод в «Queued follow-up inputs», не начиная сессию;
- `codex doctor` сам не завершается.

Квота codex при этом целая (7d — 24%).

`codex doctor` называет причину прямо: **`app-server background server socket
is stale or unreachable`**, и `codex app-server daemon version` подтверждает —
`failed to connect to C:\Users\user\.codex\app-server-control\app-server-control.sock`
(«конечный компьютер отверг запрос на подключение», os error 10061). В папке
`~/.codex/app-server-daemon/` нет ни `settings.json`, ни pid-файлов. Сессия
codex поднимается через этот демон, поэтому TUI и застревает на
`model: loading`.

Чинится это на стороне codex, не плагина: поднять демон заново
(`codex app-server daemon` или `codex update`). Вашу установку codex я не
трогал — это за пределами задачи.

Плагин в этом случае честно отвечает `queued: true` и **второй раз задачу не
шлёт**, чтобы она не пришла дважды.

Если почините codex — проверьте пункт 3 с `--kind codex`, и тогда условие
готовности закроется целиком.

## Отдельно: режим разрешений

Файл задачи лежит в папке состояния плагина, а не в репозитории. Читать её
claude разрешено — запуск передаёт ему `--add-dir` с этой папкой. А вот
**править** файлы без подтверждения решает ваш режим разрешений, и в `manual
mode` агент спросит разрешения дописать план в свой же файл задачи.

Плагин режим за вас не меняет — это ваш выбор. Не хотите подтверждать:

```
node .../bin/launch.js … --permission-mode acceptEdits
```

Скилл сам этот флаг не добавляет; скажите ему, если нужно.

## Отдельно: ваш глобальный хук

В каждой новой сессии Claude Code — и в запущенных агентах тоже — в переписке
мелькает:

```
⎿  UserPromptSubmit hook error
⎿  Failed with non-blocking status code: node:internal/modules/cjs/loader:1386
```

Это `Cannot find module`: какой-то хук в вашем `~/.claude/settings.json`
(похоже, сторож `zadacha/hooks/guard.mjs`) указывает на несуществующий путь.
К плагину отношения не имеет и ничего не ломает — хук объявлен non-blocking, —
но видно его будет у каждого запущенного агента.

остаются на месте — это обычные вкладки herdr.
