# herdr_plugins

Плагины для herdr, сделанные под свою среду: herdr 0.9.1, **нативная Windows 11**, собственная сборка из форка `VladPatr96/herdr`.

## Правило проекта: плагин здесь пишется свой, на Node

Каждая задача этого проекта трижды приходила к одному и тому же выводу, поэтому он записан правилом:

- **Готовый плагин из каталога herdr, как правило, не годится.** Большинство объявляет `platforms = ["macos", "linux"]`, ставится bash-скриптами и запускает хуки через `sh` / `python3`. Те, что объявляют `windows`, — это Rust или Go со сборкой, PowerShell-доставкой бинарника и обходными лаунчерами. Проверять каталог перед работой всё равно нужно (разведка), но рассчитывать на готовое — нет.
- **Своя форма плагина:** Node 18+, **без зависимостей и без сборки**, `platforms = ["linux", "macos", "windows"]`, установка через `herdr plugin link`. Примеры — `agent-hotkeys/`, `quota-board/`.
- **Чужой код — источник решений, а не основа.** Из MIT-плагинов снимается карта источников данных и приёмы; форк и перенос чужой кодовой базы отвергаются по цене сопровождения — [ADR 0001](docs/adr/0001-svoy-plagin-vmesto-forka-chuzhogo.md).

### Что уже известно про herdr на Windows

- Команда панели `[[panes]]` не может быть **относительным исполняемым файлом** — herdr на Windows его не запустит. Наша форма (`node` из `PATH` плюс относительный путь к скрипту аргументом) это обходит сама.
- Разрешение `PATHEXT`-шимов (`npm.cmd`, `bun.cmd`) работает для build-, action- и event-команд, но **не** для команд панелей.
- Панель плагина — настоящий PTY (ConPTY): получает весь ввод, кроме префикса `ctrl+b` и клавиш **беспрефиксных** привязок из `config.toml`. Сейчас там заняты `alt+1…alt+0`, `alt+q…alt+m` (`agent-hotkeys`) и `alt+shift+q`, `alt+shift+o` (`quota-board`) — эти клавиши до TUI в панели не доходят.
- Рабочую папку активного агента процесс панели берёт из `HERDR_PLUGIN_CONTEXT_JSON` (`focused_pane_cwd`); `HERDR_PLUGIN_STATE_DIR` пробрасывается хукам и действиям, но не панелям.
- Конфиг herdr лежит в `%APPDATA%\herdr\config.toml`. Junction в домашнем каталоге читается только через `realpathSync`; `HOME` в Git Bash — POSIX-путь, на win32 берётся `os.homedir()`.
- Изменения вне репозитория (подменённые бинарники, правки конфига) записываются в `todo-task-<номер>.md` вместе со способом отката.

## Штаб hq

Задачи, решения и память по этому проекту живут в штабе `D:/projects/my_projects/hq`, карточка — `projects/herdr_plugins/README.md`.

- **Что в работе** — раздел «Открытые задачи» в карточке и файлы `projects/herdr_plugins/tasks/<номер>-<slug>.md`. Это зеркало GitHub Issues: руками не правь, оно пересобирается.
- **Что уже решали** — «Память решений» в карточке и разборы в `projects/herdr_plugins/memory/`. Упёрся или задача похожа на прошлую — сперва посмотри туда, а не решай заново.
- **Что было в прошлых сессиях** — выжимки в `projects/herdr_plugins/sessions/`: их сохраняют хуки при сжатии и сбросе контекста. Перед новой задачей посмотри выжимки по теме — номер задачи, `topic` и `keywords` во frontmatter.
- **Задача** — один GitHub issue с меткой `task` и проверяемым условием готовности. Заводит его человек: командой `/zadacha` или своим «да» на черновик в `/dopros`; без этого issue не создавай.
- **Замысел без ясной цели** — `/dopros`: допрос идёт внутри задачи, её тело — карта, области — sub-issues с меткой `dopros:<тип>`. Области — не задачи: на доску и в таблицу задач не попадают.
- **Состояние** — метки `status:todo`, `status:in-progress`, `status:acceptance`; Done — закрытый issue. В `Done` переводит только человек.
