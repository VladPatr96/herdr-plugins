# Agent Tasks

Отдайте задачу не субагенту, а **целой сессии агента**. Она открывается
отдельной вкладкой herdr, стоит в сайдбаре со своей задачей, статусом и
чек-листом плана — и в неё можно войти и продолжить разговор.

```
✳ claude                             Alt+8
  Починить парсер дат                 2/5
  → Прогнать весь набор тестов
```

Субагент работает молча и вернуть его в диалог нельзя. Этот плагин запускает
обычного агента: из Claude Code вы говорите «запусти агента на такую-то
задачу», а дальше он ваш собеседник, как любая другая сессия.

Работает на Linux, macOS и Windows, требует herdr 0.9.1 и Node 18. Ставит
только то, что ставится: зависимостей нет.

## Установка

```bash
herdr plugin install VladPatr96/herdr-plugins/agent-tasks
```

Дальше два шага — один обязательный, второй тоже.

**1. Скилл для Claude Code.** Claude Code не умеет находить плагин herdr сам,
поэтому скилл ставится отдельной командой — она подставит в него путь:

```bash
herdr plugin action invoke install-skill --plugin vladpatr96.agent-tasks
```

После этого в Claude Code появляется `/zapustit-agenta`. Убрать —
`remove-skill`.

**2. Строка задачи в сайдбаре.** herdr показывает токены плагина только там,
где вы их попросите. Добавьте в `config.toml` третью строку агента:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "machine", "workspace", "tab"],
  ["agent", { token = "$hotkey", align = "right" }],
  [{ token = "$task", bold = true }, { token = "$task_progress", align = "right", fg = "#f9e2af" }],
]
```

`align` есть не во всех сборках herdr; без него уберите его из строки — задача
и прогресс встанут подряд через ` · `. Строка с токенами **пропадает у агентов,
запущенных не этим плагином**: herdr прячет строку, у которой ни один токен не
заполнен, — так что остальные агенты выглядят как раньше.

Строку видно после `herdr server reload-config`.

## Как этим пользоваться

**Поставить задачу.** В Claude Code:

```
/zapustit-agenta почини парсер дат в src/import, моделью sonnet
```

Скилл соберёт из разговора самодостаточный текст задачи (агент стартует с
чистым контекстом и про ваш разговор ничего не знает), запустит агента и
скажет, каким хоткеем в него войти. И на этом остановится: дальше задача — его.

**Список сверху, агент под ним.** Действие
`Agent Tasks: open the board in a side pane` — окно со всеми запущенными
агентами, их задачами, статусами и планами. Выбираете агента — **его панель
переезжает под список**, а та, что стояла там до него, уезжает обратно к себе.
Список никуда не девается, агенты сменяются под ним.

```
┌──────────────────────────────────┐
│ Агенты и их задачи               │
│  1 ✳ Починить парсер дат    3/7  │
│ ▸2 ◐ Собрать отчёт          1/4  │
│    codex · Alt+2 · работает · рядом
├──────────────────────────────────┤
│ ◐ Собрать отчёт                  │
│                                  │
│ ● Считаю по выгрузке за март     │
│ ❯                                │
└──────────────────────────────────┘
```

Направление задаётся `AGENT_TASKS_BOARD_SPLIT`: `down` (по умолчанию — агент
под списком) или `right`, если список открыт во всю ширину.

| Клавиша | Что делает |
|---|---|
| `↑` `↓` (или `k` `j`) | выбрать агента; список замкнут в кольцо |
| `Enter` | показать выбранного рядом со списком |
| `1`…`9` | показать сразу агента с этим номером |
| `o` | отпустить: агент уезжает к себе, рядом снова пусто |
| `p` | развернуть чек-листы планов |
| `r` | обновить |
| `q`, `Esc` | закрыть (агент при этом уезжает домой) |

Курсор `▸` и пометка `рядом` — разные вещи: первый показывает, на ком вы
стоите, вторая — чья панель сейчас на экране.

Агент при этом **остаётся собой**: у него тот же хоткей, та же строка в
сайдбаре, та же сессия. Меняется только, в какой вкладке стоит его панель.
Уезжая, он забирает с собой название вкладки — задачу видно и в сайдбаре.

**Убрать их из сайдбара.** Когда агент и так виден под списком, вторая его
строка в панели «Agents» только мешает. Действие
`Agent Tasks: hide these agents from the sidebar` прячет её, обратное —
`show these agents in the sidebar again`.

Прячет не плагин, а сам herdr: у него есть отбор для этой панели
(`agent.view.set`), и отбирает он по токену `$task`, который ставит только
этот плагин. Поэтому **чужие агенты остаются на месте**, а `agent list`,
события и хоткеи продолжают видеть всех — прячется только строка. Выбор
запоминается и восстанавливается после перезапуска сервера.

У отбора один владелец на всю сессию: если панель уже отбирает кто-то другой,
наш его вытеснит.

Долю, остающуюся списку, задаёт `AGENT_TASKS_BOARD_RATIO` (по умолчанию
`0.35`).

**Оверлей** (`Agent Tasks: open the board`) — второй вид того же окна, для
«зашёл, глянул, ушёл»: он наезжает на активную панель и держать соседа не
может, поэтому просто уводит фокус в агента и закрывается.

**Войти в сессию иначе.** `Alt+N` из сайдбара или мышью по строке — это то же
самое. Внутри обычная сессия агента: видна его переписка, можно спросить и
получить ответ.

**Запустить codex.** То же самое, `--kind codex`: он попадает в тот же список,
и управляется оттуда же.

## Что видно в сайдбаре

| Токен | Значение |
|---|---|
| `$task` | заголовок задачи |
| `$task_progress` | `2/5` — сколько пунктов плана отмечено |
| `$task_step` | пункт, за которым агент сейчас |

Статус не токен: `state_icon` и `state_text` у herdr свои, он их сам и меняет.
Плагин добавляет только то, чего herdr знать не может, — какая это задача и
где агент в своём плане.

## Откуда берётся чек-лист

План ведёт сам агент — Markdown-чеклистом в файле своей задачи:

```markdown
## План

- [x] Воспроизвести падение тестом
- [ ] Починить разбор
- [ ] Прогнать весь набор
```

Промт при запуске просит его об этом и объясняет зачем: по этому файлу человек
в сайдбаре видит, где агент. Плагин файл только читает.

Чек-лист в тексте самой задачи планом не считается — в счёт идёт только раздел
«План».

Почему файл, а не хук агента: хуки Claude Code до codex не достают, а половина
агентов хуже, чем простой текст, который пишут оба.

## Как устроено

Запуск — три штатные команды herdr, ничего своего:

1. `herdr tab create --cwd <папка>` — своя вкладка, чтобы агент встал в сайдбар
   рядом с остальными и получил свой хоткей;
2. `herdr agent start <имя> --kind claude --pane <id> -- --model sonnet` —
   herdr сам набирает агента в оболочке и ждёт, пока тот отзовётся;
3. `herdr agent prompt <id> <указатель на файл задачи>`.

Задача уходит **файлом, а не текстом промта**: многострочный текст с кавычками
не переживает ни оболочку, ни ввод агента, а путь переживает всё. Тот же файл
несёт обратно план — задача и её чек-лист лежат вместе.

Статусы плагин не изобретает: `agent_status` у herdr свой, и его изменения
приходят сюда событиями `pane.agent_status_changed`.

- `bin/launch.js` — запуск; печатает JSON для вызвавшего скилла.
- `bin/sync.js` — метки в сайдбар; висит на событиях и на старте сервера.
- `bin/board.js` / `bin/open.js` — окно со всеми агентами. Показать агента
  под списком — это `herdr pane move <агент> --tab <вкладка списка> --split down`;
  herdr сам закрывает опустевшую вкладку агента и сам переводит на него фокус.
  Обратно панель уезжает через `--new-tab`, и название задачи возвращается ей
  командой `tab rename`.
- `bin/install-skill.js` — скилл для Claude Code с подставленным путём.
- `bin/sidebar.js` / `lib/socket.js` — отбор панели «Agents». Единственное
  место, где плагин говорит с herdr не через `herdr`, а прямо в сокет:
  у `agent.view.set` обёртки в CLI нет.
- `lib/` — чистые функции: разбор чек-листа, токены, отрисовка доски.

Реестр запущенных агентов и файлы задач лежат в `HERDR_PLUGIN_STATE_DIR`.

## Пределы

- **Агент может спросить разрешения дописать план.** Файл задачи лежит в папке
  состояния плагина, а не в репозитории; claude получает к ней доступ флагом
  `--add-dir`, поэтому **читает** её без вопросов. А вот правит ли он файлы без
  подтверждения — это ваш режим разрешений, и плагин за вас его не меняет.
  Надоело подтверждать — передайте режим явно:
  `bin/launch.js … --permission-mode acceptEdits`.
- **Задачу запущенному агенту не переписать.** Хотите другую — входите в сессию
  и говорите ему, как любому собеседнику.
- **Промт может не дойти с первого раза.** Пока TUI агента перерисовывается,
  набранный в него текст пропадает или примешивается прямо к заставке. Запуск
  поэтому сперва ждёт, когда экран перестанет меняться (два одинаковых снимка
  подряд), и только потом печатает; если и это не помогло — замечает и
  повторяет. Если агент
  ещё поднимает сессию и держит ввод в очереди (так ведёт себя codex на
  холодном старте), запуск честно отвечает `prompted: false, queued: true` и
  **не шлёт задачу второй раз** — иначе она придёт дважды.
- **Агент, закрывший вкладку, уходит из реестра**, и строка из сайдбара
  пропадает. Файл задачи с планом остаётся — по нему видно, чем кончилось.
- **Законченная задача не закрывает пейн.** Статус задачи и жизнь терминала —
  разные вещи: агент может всё отметить и остаться ждать следующего вопроса.
- **Агент встаёт в тот воркспейс, откуда его позвали**, а не туда, где лежит
  папка задачи: herdr задаёт `HERDR_WORKSPACE_ID` в каждом своём пейне, и
  запуск берёт его оттуда. Если вызвать `bin/launch.js` не из пейна herdr
  (сторонний терминал, расписание), воркспейс ищется по рабочей папке, а не
  найдётся — вкладка уйдёт туда, где herdr сочтёт себя текущим.
- Ветки и worktree плагин не трогает: агент работает в той же папке, что и вы.
