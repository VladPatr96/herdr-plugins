# zapustit-agenta — отдать задачу живому агенту

Субагент работает молча и вернуть его в диалог нельзя. Этот скилл заводит
**обычную сессию агента** в отдельной вкладке herdr: её видно в сайдбаре, в неё
можно войти по хоткею и спросить, как у неё дела.

Скилл **ставит задачу и уходит**. Не выполняй её сам, не жди, пока агент
закончит, и не пересказывай его работу: с этого момента она его.

Аргумент: `$ARGUMENTS`

## 1. Собрать задачу

Агент начинает с чистым контекстом и ничего не знает про этот разговор.
Поэтому текст задачи — **самодостаточный**: что нужно получить, где это лежит
и по чему будет видно, что готово. Не пересказ диалога.

Возьми из аргумента и из этой сессии:

- **заголовок** — «Объект — действие», коротко, он пойдёт в сайдбар;
- **задачу** — несколько абзацев: что сделать, в каком проекте, что уже
  известно, что считать готовым;
- **род агента** — `claude` по умолчанию, `codex` если попросили;
- **модель** — из аргумента (`sonnet`, `opus`, `haiku`, `gpt-5.1-codex`).
  Не назвали — не передавай `--model`, агент возьмёт свою обычную.

Не уверен, чего человек хочет от агента, — спроси **одним** вопросом через
инструмент AskUserQuestion и только потом запускай. Запущенному агенту задачу
уже не переписать.

## 2. Запустить

Запиши задачу во временный файл (Write), затем:

```bash
node "PLUGIN_ROOT/bin/launch.js" \
  --kind claude \
  --model sonnet \
  --title "<заголовок>" \
  --task-file "<файл с задачей>" \
  --cwd "<рабочая папка проекта>"
```

- `--cwd` — папка, в которой агент должен работать. По умолчанию берётся папка
  текущей сессии; если задача про другой проект, укажи его папку явно.
- `--kind codex` запускает codex тем же способом и в тот же список.
- `--focus` переключит на агента сразу; без него человек остаётся у себя.
- `--permission-mode acceptEdits` — если человек не хочет, чтобы агент
  спрашивал разрешения дописать свой план. Сам не добавляй: режим разрешений
  человек выбирает себе, а не ты ему.

Скрипт печатает JSON: `paneId`, `tabId`, `hotkey`, `taskFile`, `prompted`.

## 3. Доложить

Скажи человеку три вещи и остановись:

1. Что запущено и какой моделью.
2. **Как войти:** хоткей из `hotkey` (например, `Alt+7`) или мышью по строке в
   сайдбаре. Внутри — обычная сессия: можно спросить и получить ответ.
3. Где план: `taskFile`, раздел «План». Чек-лист ведёт сам агент, а сайдбар
   показывает `3/7` рядом с задачей.

Разбор по полям ответа:

- `ok: false, stage: "start"` — агент не поднялся. Вкладка осталась, в ней
  живая оболочка: скажи это человеку и покажи `error`, не запускай вторую.
- `prompted: false` — агент запущен, но задачу за отведённое время не взял:
  он ещё поднимает сессию и держит ввод в очереди, а запустит её сам. Так
  ведёт себя codex на холодном старте. Скажи как есть: «задача отдана, агент
  ещё просыпается», — и не отправляй её второй раз, иначе задача придёт дважды.

## Что скилл не делает

- Не следит за агентом и не докладывает о его ходе: это делает сайдбар.
- Не закрывает агента. Закончил — человек закрывает вкладку, и строка уходит
  из реестра сама.
- Не заводит задачу в GitHub: для цикла задач есть `/zadacha`.
